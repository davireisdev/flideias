## Priority Issues

**[P0] Every real submission is silently and permanently lost — and the confirmation message says so.**
- Why it matters: `FormSection.jsx`'s handleSubmit only sets local React state; no backend/storage/e-mail integration exists. The visible confirmation text literally admits "envio ainda não conectado a nada" at the highest-stakes moment in the flow.
- Fix: Wire at minimum a lightweight relay (EmailJS, a small function, or an interim mailto: pre-fill) before going live; if shipping before that's ready, change the copy so it doesn't admit the gap and offer a WhatsApp/e-mail fallback nudge.
- Suggested command: $impeccable harden

**[P1] WCAG AA contrast fails on the primary CTA and three secondary text roles.**
- Why it matters: Primary button (bg-accent-500 text-white) measures 4.20:1 against the 4.5:1 AA threshold, confirmed three ways (detector, manual math, the design token itself). Footer copyright (white/25, 2.10:1), "Prefere falar direto?" label (white/30, 2.53:1), and the idea-textarea placeholder (white/30, 2.69:1) all fail outright. The "Em breve" badge also fails on size (10px vs DESIGN.md's 12px floor).
- Fix: Token-level fix — darken accent-500 for button text (or swap to #f4f3fb on a deeper violet), and raise the opacity floor for functional text below white/50 (which passes at 5.37:1).
- Suggested command: $impeccable harden (accessibility pass) or $impeccable audit for a full contrast sweep

**[P1] The "Pronto" nav link lands on a visually broken screen.**
- Why it matters: Re-verified with scrollY-settle polling: clicking "Pronto" leaves the Formulário section's submit button/AI panel overlapping the fixed nav, followed by ~400px of dead space before the closing message. Root cause: no scroll-margin-top on any section ID, combined with ClosingSection's min-h-[70vh] justify-center. The control link ("Sua ideia") landed clean in this same test, though Assessment B separately observed clipping-like behavior near Formulário via a different scroll path — the same missing scroll-margin-top would explain both.
- Fix: Add scroll-margin-top (~96px) to all three section IDs; reconsider min-h-[70vh]+justify-center as an anchor-jump target for ClosingSection.
- Suggested command: $impeccable layout

**[P1] Uploaded images can't be removed on mobile, and there's no draft recovery.**
- Why it matters: ImageUploader.jsx's remove button is opacity-0 group-hover:opacity-100 with no touch/focus equivalent. No localStorage or beforeunload guard exists, so reloading (the only recourse on mobile) wipes the entire form.
- Fix: Make the remove control always visible below a breakpoint; consider persisting form state to localStorage as a safety net.
- Suggested command: $impeccable harden

**[P2] Empty submissions succeed with the same confirmation as a complete brief.**
- Why it matters: No validation exists anywhere in FormSection.jsx — undermines the product's own stated purpose of gathering enough info to start a project.
- Fix: Require at least the idea description before allowing submit, using a soft, on-tone nudge.
- Suggested command: $impeccable harden
